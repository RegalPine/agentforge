# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

We take security vulnerabilities seriously. If you discover a security issue, please report it responsibly.

### How to Report

**Please do NOT open a public GitHub issue for security vulnerabilities.**

Instead, please report via:

1. **GitHub Security Advisories** (preferred): Go to the [Security tab](https://github.com/regalpine/agentforge/security) → [Report a vulnerability](https://github.com/regalpine/agentforge/security/advisories/new)
2. **Private email**: Contact the maintainers directly

### What to Include

- Description of the vulnerability
- Steps to reproduce or proof of concept
- Affected versions
- Potential impact assessment
- Suggested fix (if any)

### What to Expect

- **Acknowledgment**: Within 48 hours of receipt
- **Assessment**: We will evaluate the severity and impact within 5 business days
- **Updates**: Regular progress updates as we work on a fix
- **Disclosure**: We will coordinate with you on the public disclosure timeline

### Security Update Process

- Critical vulnerabilities will be patched as soon as possible
- Patches will be released for the latest stable version
- Security advisories will be published after a fix is available
- CVE IDs will be assigned when appropriate

## Security Best Practices for Users

- Always use the latest stable version
- Review dependency updates regularly (Dependabot is enabled)
- Follow the principle of least privilege when configuring credentials
- Use HTTPS for all API communications
- Rotate API keys and secrets regularly
